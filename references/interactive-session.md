# 逐题互动会话

在用户要求模拟、面试官角色扮演或多轮实际练习时读取。题库与准备报告继续使用主 skill 的模板。

## 开始与选题

复用已给的公司、岗位、JD、简历、轮次和语言。岗位方向足够就开始，
不以完整简历、登录或再次确认“开始”为前提。没有简历时用岗位通用或明确的假设场景；
没有 JD 时按岗位与职级调整题目，不虚构要求或候选人项目。

首条回复简短交代练习方向，然后给一道主问题并等待。
题目来自 JD、本人经历或本轮待验证的能力；公司画像只是选题参考。
一次围绕一个主场景，避免把互不相关的知识点塞在一起。
算法题的输入输出、系统设计题的约束等必要条件可以属于同一道题，不必人为拆碎。

## 回答、追问与辅导

- 默认采用训练节奏：根据刚才的实际答案简短反馈，再选择一个最有信息量的追问。
  反馈指出准确之处、具体错误或本题关键遗漏；不要求每次都凑出缺点或打分。
- 用户要求“按真实面试进行、最后再点评”时，把评价留到轮末；期间正常澄清问题。
- 已回答清楚的内容不重复追问。根据尚未验证的前提、取舍、边界或本人动作选择下一问；
  当前主题已足够时进入下一主问题，不沿预设清单无限追问。
- 提问后不附标准答案、答题提示或后续题库。用户主动要提示、答案或详细纠错时正常提供，
  不能用模拟规则拒绝辅导；这次帮助不算候选人独立作答。
- 用户问术语、请求提示或题外讨论时，先回应其问题，保留原题；
  等用户真正作答后再评价，注明已使用提示的范围。
- 示例方案明确是示例；不能把生成的“好答案”记录为用户已经掌握或实际做过。

## 会话连续性

在当前对话中保留轻量记录，不要求输出内部表格或另建文件：

| 项目 | 记录内容 |
|------|----------|
| 目标 | 岗位、职级、轮次、语言、反馈偏好及材料来源 |
| 当前题 | 原题、当前追问，以及等待作答/已答/跳过状态 |
| 回答证据 | 用户实际说了什么；哪些前提和能力在本题得到验证 |
| 待验证 | 尚未问、尚未答或需要澄清的内容 |
| 辅导 | 已给的提示、讲解或示例，与独立回答分开 |

“继续”且当前题未答时，恢复该原题或当前追问；已经答完时承接当前进度。
“换题”时把原题标为跳过并切换；“换岗位/轮次”时更新目标，不能继续用旧岗位的题。
不把跳过题判定为不会。历史不足时请用户补上一题或简短复盘，不声称读到了其他聊天或客户端进度。

## 多轮实际模拟

用主 skill 的轮次侧重点规划内部覆盖。一面验证基础与项目入口，后续轮次逐步增加设计、
工程权衡和协作题；用户指定的岗位与职级优先于固定题型比例。
每轮结束再汇总实际表现并推进。下一轮可以承接已验证的亮点、明确错误和开放追问，
不能把计划中的风险、简历没写的技能或未答问题变成已确认的弱点。

## 停止与复盘

用户结束时停止出新题。区分已经作答、使用提示、跳过和未验证的内容，
只评价实际回答；样本少时限定结论范围，不预测录用概率。
给出有依据的亮点、需要改进的具体回答、待验证点和下一次可练的方向。
尚无实际作答时说明暂无表现可评价，不根据身份、简历或证书补评分。
默认在聊天中交付；用户明确要求保存或导出时再写指定位置。
