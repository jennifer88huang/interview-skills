# 简历解析维度说明

> 在 Step 2 中调用，从简历提取面试出题素材。

---

## 解析输出格式（内部使用）

```
简历解析结果：
- 教育背景：[学校层次 + 专业 + 毕业时间]
- 工作年限：[X 年]
- 职业轨迹：[公司1 → 公司2 → ...]
- 亮点项目（Top 2~3）：
  - 项目名：
  - 规模/数据：[QPS/DAU/金额等]
  - 候选人角色：[独立负责 / 参与 / 主导]
  - 技术栈：
- 核心技术栈：
- 待确认信息：[材料未覆盖的 JD 要求或项目细节]
- 明确差距：[用户自述或实际回答中的证据；没有则不填]
- 可追问的亮点：[可以深挖的话题]
```

---

## 解析策略

### 数字挖掘
从简历中提取量化数字，并保留环境、范围、基线与测量口径；未知不补值。这些可以作为追问素材：
- 「QPS 10万」→ 出题：「10万 QPS 是峰值还是平均？怎么压测出来的？」
- 「支持 3000万 用户」→ 「这 3000万 用户同时在线有多少？DB 怎么扛的？」
- 「负责 XX 模块研发」→ 「你具体负责哪些决策和实现，怎样与其他成员分工？」

### 时间轴分析
- 在职时间较短：与 HR 主题相关时中性询问变动背景，不认定是所有公司的必问题
- 多次变动：「这些经历之间的选择背景是什么？」不从时间轴直接判断稳定性或动机
- 长期在同一家公司：「你在 XX 公司 5 年，为什么现在想离开？」

### 技术栈差异
对比 JD 技术栈 vs 简历技术栈：
- 有交集：从交集出深度题
- 材料未提及：「JD 提到 XX，你是否有相关学习或实践可以补充？」确认后再区分真实差距
- 有意外加分项：「你简历上有 Rust 经验，在什么场景下用的？」

### 项目规模判断
| 描述词 | 实际规模判断 | 对应问法 |
|--------|------------|---------|
| 「大规模」「亿级」 | 需验证 | 「你们的 QPS 峰值是多少？」 |
| 「参与研发」 | 本人职责待确认 | 「你具体负责哪些模块、决策或实现？」 |
| 「主导/负责」 | 按原角色记录，确认范围 | 「团队怎样分工，你负责的范围是什么？」 |
| 「优化了 XX%」 | 需要背景 | 「优化前 baseline 是多少？怎么测量的？」 |

## 简历缺失信息处理

如果用户没有上传简历：
- 可邀请补充与本次练习有关的经历；岗位方向足够时直接进行通用练习，不反复要求简历。
- 题目按 JD/岗位和已知职级设计；明确是假设情境，不借“理想候选人”画像编造本人项目。

解析和评价遵循 [事实与复盘依据](evidence-review.md)。

## 简历格式支持

| 格式 | 处理方式 |
|------|---------|
| PDF | Read 工具直接读取 |
| 图片（PNG/JPG）| Read 工具 OCR 识别 |
| Word/DOCX | 提示用户导出为 PDF 或复制文字 |
| 文字粘贴 | 直接解析 |
| 无简历 | 见上方「缺失信息处理」 |
